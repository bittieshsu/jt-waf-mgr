# jt-waf-mgr 戰情室規格 (v0.1，2026-11-15)

> 本文件可公開。範例網域與位址一律使用 `example.com` 與文件用 IP 區段 (RFC 5737)，數字都是合成的。
> 依設計師稿 v1 (畫面、互動原型) 實作；設計稿本身不隨專案發佈。

## 1. 目的

管理頁已經能完成調查與變更。戰情室給離牆面數公尺的值班人員看：**什麼正在變化、要找誰、該開哪筆證據**。
入口在「總覽」下拉選單，點了**開新分頁** (`/warroom`)，全螢幕、不帶管理介面的選單，可以放在電視牆上輪播。

## 2. 七個畫面 (輪播)

1. **全球事件地圖 (2D)**：國家中心點到入口的弧線、近 30 分鐘外部來源排行 (事件數、不同來源數、封鎖與只記錄比例)、
   每分鐘事件強度、最新事件。值班預設首頁。
2. **即時防禦地球 (3D)**：正射投影地球，可拖曳、停止自轉、選國家定位；新事件以曳光從來源落向入口，封鎖時顯示攔截環。
   與 2D 使用同一組數字。
3. **封鎖決策流**：外部/內網 → 確定規則、CRS 分數、其他、只記錄 → 結果的流帶圖，單位是事件數。
4. **站台熱區**：每站一列、每兩分鐘一格；有事件、零事件分開列。
5. **誤判檢討**：只靠 CRS 分數封鎖的事件按站台分組，內網只記錄與外部只記錄分開。
6. **AI 與威脅情報**：第一層分析的最近一輪 (候選、有效判斷、提案分開計)；第二層的產品確認、影響與已被利用的依據。
7. **警示與變更**：待處理警示與變更分開，各自有編號、階段、等待時間。

## 3. 即時資料

- 進入時取**快照** `GET /api/v1/warroom/snapshot`：`window_start`、`window_end`、`node_id`、`high_water_id`、
  收集狀態與 30 分鐘視窗的彙總 (伺服器對完整區間計算，不用前端已載入的筆數)。
- 之後每 5 秒取增量 `GET /api/v1/warroom/events?after=<id>`：以事件 ID 遞增接續、去重；用事件時間決定時間桶；
  遲到的事件補回原時間桶，不當成現在的攻勢重播。沒有新事件也回伺服器時間 (心跳)。
- 每分鐘重新對齊快照；游標失效、斷線過久或落後太多時重取快照，顯示「補同步中」。
- 四種狀態要看得出來：**停收** (收集器停止或落後)、**安靜** (正常但沒有事件)、**斷線** (連不到伺服器，保留最後數字與截至時間、
  停止動畫)、**補同步**。
- 多個螢幕共用伺服器端的摘要快取 (同一份快照 5 秒內只算一次)。

## 4. 顯示的資料與隱私

- 牆面**不顯示**來源 IP、網址路徑、查詢字串、內部站台名稱：戰情室端點根本不輸出這些欄位 (不是前端截短)。
  內部專用的站台以別名顯示。要看原始事件時，點下鑽連結回到管理頁 (依登入者權限)。
- 國家只是來源的 GeoIP 定位，不代表攻擊者實際所在地；沒有新事件就不發射動畫；動畫不代表已確認入侵或封包路由。
- 事件數與不同來源數分開列；封鎖率的分母是同站同時段的請求數，收集不完整時顯示「無法計算」。

## 5. 入口位置 (目的地)

- 管理者在設定頁填目前 WAF 節點的公開顯示名稱與座標 (精度到城市即可)。
- 沒有填時：2D 只顯示來源脈衝，3D 只標來源，不畫目的地。

## 6. 操作

- 頁籤、左右方向鍵切換；輪播 (每頁秒數可設，預設 25 秒)；全螢幕；「釘選畫面」「暫停動畫」「凍結資料」三個獨立控制。
  凍結時保留截至時間，恢復時先補摘要，不把累積的事件瞬間播成新攻勢。
- 點國家、站台、事件 → 側邊詳情 (同一時間窗)，再一步連到管理頁。
- 偏好「減少動態」時關閉曳光與自轉，數字照常更新；瀏覽器分頁隱藏時暫停繪圖。
- 戰情室**只讀**：輪播、開卡都不會觸發分析或寫入任何東西。登入過期時清空畫面並顯示重新登入。

## 7. 分期

1. 2D、3D、共用即時資料、事件下鑽、輪播與唯讀顯示。
2. 決策流、站台熱區、誤判檢討。
3. AI 與威脅情報、警示與變更。

## 8. 驗收

- 同一批測試資料切換 2D 與 3D，來源、件數、處置與時間窗一致；沒設定入口時兩頁都不畫目的地。
- 停收、安靜、斷線、補同步四種狀態可辨識。
- 重複 ID、跨分鐘事件、刪除舊資料、記錄輪替、跨時區零點都正確。
- 1,000 件同窗突發時畫面仍流暢 (超載先省略特效)；長英文站名與日文不破版。
